# Marketing Agent

An AI marketing-content pipeline for **Ocass** (super app) and **Intercity
Travel** campaigns: turn a short campaign brief into per-platform captions,
hashtags, a branded flyer image, and a promo-video script — with a human
approval step before anything is considered "published".

## What this does (and doesn't) do

- **Copy generation** (Claude): real, working. Generates a flyer
  headline/subtext plus 3 caption variants + hashtags per platform
  (Instagram, Facebook, WhatsApp, TikTok), in French by default.
- **Flyer image** (local rendering): real, working. Composites the
  headline/subtext onto a branded background PNG using `sharp` — **no
  external design API or account needed**. See "Canva" note below for why.
- **Video script**: real, working, but it's *only* the script/storyboard
  text. Turning that into an actual video clip needs a text-to-video vendor
  (Runway, Pika, etc.) — that render step is a documented stub, not
  implemented, so picking/paying for a vendor is a deliberate follow-up
  decision, not something wired in blindly.
- **Publishing to social platforms**: a stub. `POST /:id/publish` flips the
  campaign's status and returns a note — it does **not** call Meta Graph API
  or WhatsApp Business API. Real posting needs per-account OAuth credentials
  that don't exist yet, and auto-posting shouldn't happen without those
  being deliberately wired in.

### Why not Canva?

The original design used Canva's brand-template "autofill" API to render
flyers. That API (`/v1/brand-templates*`, `/v1/autofills*`) is gated to
**Canva Enterprise** accounts only. Since Enterprise access wasn't confirmed
available, flyer rendering was done locally instead (`src/lib/flyer.js`) —
this needs zero external API keys/OAuth and produces a comparable flyer
image. If Enterprise access is obtained later, swapping `flyer.js` for a
Canva Connect API call is a contained change (only `routes/campaigns.js`'s
`/design` handler and a new `lib/canva.js` would need to change).

## Setup

```bash
cd marketing-agent
npm install
cp .env.example .env
# edit .env and set ANTHROPIC_API_KEY
npm run setup:assets   # regenerates placeholder brand backgrounds (already committed, only needed if you edit the script)
npm start              # http://localhost:4100
```

`ANTHROPIC_API_KEY` is required for the `/copy` and `/video-script`
endpoints; nothing else needs credentials.

### Replacing the placeholder flyer backgrounds

`assets/templates/ocass/background.png` and
`assets/templates/intercity/background.png` are plain placeholder images
(solid color + app name) generated by `scripts/generate-placeholder-templates.js`
just so the pipeline works out of the box. **Replace these two files with
real designed brand backgrounds** (1080x1080 PNG recommended) before using
this for an actual campaign — the flyer renderer just overlays text on
whatever PNG is there.

## Campaign lifecycle

```
draft -> copy_generated -> design_generated -> approved -> published (stub)
```

A failed step (Claude error, render error) returns a 502/500 and leaves the
campaign's status unchanged, so retrying the same step is always safe.

## API

- `POST /api/campaigns` — create a campaign brief
  ```json
  {
    "app": "ocass",           // or "intercity"
    "goal": "...",
    "keyMessage": "...",
    "offer": "...",            // optional
    "targetAudience": "...",
    "platforms": ["instagram", "facebook", "whatsapp", "tiktok"],
    "language": "fr"            // optional, defaults to fr
  }
  ```
- `GET /api/campaigns` / `GET /api/campaigns/:id`
- `POST /api/campaigns/:id/copy` — generate captions/hashtags/flyer text via Claude
- `POST /api/campaigns/:id/video-script` — generate a scene-by-scene video script via Claude
- `POST /api/campaigns/:id/design` — render the flyer PNG (requires `/copy` to have run)
- `POST /api/campaigns/:id/approve` — human approval gate (requires a rendered flyer)
- `POST /api/campaigns/:id/publish` — stub, requires `approved` status

Rendered flyers are served statically at `GET /flyers/<campaignId>.png`.

## Storage

Campaigns are stored as flat JSON in `data/campaigns.json` (atomic
write-then-rename, no database) — fine for this MVP's scale. Rendered
flyers land in `data/flyers/`. Both are gitignored.
